# Skill PR #3 — Go language support

> Adds `--language go` to the `dev-project-setup` skill: gofumpt + golangci-lint + native git hooks via `core.hooksPath`. Mirrors PR #2's plan structure (which mirrors PR #1's). Reuses the engine + safety primitives + shared templates already on `main` from PR #1 + PR #2.

## Context

PR #1 (merged) shipped the bootstrap engine + Python language. PR #2 (merged) added Node-TS via Husky + Biome + vitest + TypeScript. PR #3 follows the same pattern for Go.

This is the **second PR using the skill's self-hosted bidirectional review loop** (PR #2 was the first post-bootstrap-exception PR; PR #3 inherits the discipline). Closes Codex iter-1 #7. Per [`docs/plans/README.md`](../README.md), PR #3 is split into:
- **Plan PR (this file)** — adds `docs/plans/2026-05-15-skill-pr3-go-language.md`.
- **Implementation PR** — follows after the plan PR merges. Adds `languages/go/`, small engine dispatch extensions, Jinja conditional surgery for the new third language, tests, and Bucket E doc updates.

User-decided scope constraints:
- **Hook framework**: **Native Go** — no `pre-commit` framework, no Husky. The Makefile's `install-hooks` target runs `git config core.hooksPath hooks` (mirrors Husky's pattern of pointing git at a custom hooks dir). The hook scripts at `hooks/pre-commit` + `hooks/pre-push` are versioned in the repo. **No Python or Node dependency for Go-only projects' `install` / `check` / `hooks` paths** (closes Codex iter-5 #3 — the broader "no Python deps" claim was too sweeping). The plan-review Makefile fragments (`review-plan-by-codex`, `review-plan-by-claude`) still require `python3` because `scripts/run-with-clean-env.py` is Python; that's an existing cross-language dep documented in `docs/usage.md`.
- **Go module path**: `github.com/{github_owner}/{github_repo}` when `--github-owner` + `--github-repo` are passed; falls back to bare `{project_name}` for greenfield projects without GitHub coords.

## Architecture decisions specific to Go

- **Go version**: hardcoded `go_version = "1.26"` (current stable as of 2026-05). Parallel to Python's `3.12` and Node's `24`. Variable flows through context so a future PR (or `--go-version` flag) can override.
- **Module path**: `github.com/{github_owner}/{github_repo}` when both `--github-owner` + `--github-repo` are set; falls back to bare `{project_name}` otherwise. Auto-derived — no separate `--module-path` flag. Greenfield projects without GitHub coords get a valid local module path; published projects get a proper public module path.
- **Hook framework**: **Native Go** — no `pre-commit` framework, no Husky. `hooks/pre-commit` + `hooks/pre-push` shell scripts are versioned in the repo; `make install-hooks` runs `git config core.hooksPath hooks`. Symmetric with PR #2's Husky pattern (which also sets `core.hooksPath` after running `npx husky`). **Zero Python/Node dependency for Go install/check/hooks paths** (closes Codex iter-7 #2 — earlier wording said "Zero Python or Node dependency for Go-only projects", which was contradicted by `Makefile.review.tmpl` invoking `scripts/run-with-clean-env.py` for the plan-review targets; the narrower wording matches the scope-section caveat). The plan-review targets (`make review-plan-by-codex|claude`) still require python3 — that's an existing cross-language dependency, not Go-specific.
- **Linter**: golangci-lint (orchestrator). Standard Go ecosystem choice; aggregates `go vet`, `staticcheck`, `errcheck`, etc.
- **Formatter**: gofumpt (stricter than gofmt). Standard among Go quality-focused projects; auto-fixable.
- **Test framework**: built-in `go test`. No third-party runner.
- **Project layout**: top-level `main.go` + `main_test.go` (simplest for a smoke project; idiomatic for single-binary Go projects). `cmd/<name>/` layout for multi-binary projects is parked for follow-up.
- **First-install path**: `make install` runs `go mod download` + pinned `GOBIN="$(CURDIR)/bin" go install` of gofumpt + golangci-lint binaries (project-local; closes Codex iter-3 #1). **No `go.sum` for the stdlib-only smoke project** (closes Codex iter-1 #4 — `go.sum` is absent for modules with no non-stdlib deps). When/if the user adds deps to `go.mod`, the next `go mod download` generates `go.sum` and they commit it (mirrors Node's `package-lock.json` commit step then). Generated CI ships `setup-go@v5` with `cache: false` for the no-go.sum starting state (closes Codex iter-4 #2); user re-enables `cache: true` once `go.sum` exists.

## Risks + mitigations (PR-#3-specific)

| Risk | Mitigation |
|---|---|
| Go version churn (gofumpt, golangci-lint, go itself) | Pin `go_version = "1.26"`. Document the bump flow in `shared/CONTRIBUTING.md.tmpl` (language-conditional Go section). Reasonable cadence: review the pin every Go release cycle (~6 months) |
| `golangci-lint` config schema changes (v1 → v2) | Pin schema version in `.golangci.yml.tmpl` (`version: "2"`). Template test asserts the version line is present |
| `go` not on PATH on developer's machine | `test_smoke_go_generated.py` uses `shutil.which("go")` to check up front; skips with `pytest.skip("go not on PATH")` locally; FAILS HARD when `CI=true` env var is set (same pattern as Node smoke) |
| `gofumpt` not on PATH | Generated `make install` runs pinned `GOBIN="$(CURDIR)/bin" go install mvdan.cc/gofumpt@v0.9.2` + `GOBIN="$(CURDIR)/bin" go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.12.2` after `go mod download` (closes Codex iter-4 #5: bumped golangci-lint pin to v2.12.2, current per upstream docs as of 2026-05; closes Codex iter-4 #3: `GOBIN` value quoted for path-with-spaces safety). **Project-local install** (no `$GOPATH/bin`, no PATH dependency) — closes Codex iter-3 #1 + iter-4 #1 (earlier draft's risks-table row reintroduced the global-PATH wording; this row + Bucket B are now consistent). Tools land in `./bin/`; Makefile + hooks call them as `./bin/gofumpt` and `./bin/golangci-lint` explicitly. Future bump flow: edit Makefile vars + re-run `make install`. Alternative `tools.go` build-tag approach parked |
| Hook scripts use bash-isms; Windows users don't have bash | Hook scripts use POSIX shell (no bash-only features). Document in README that Git Bash on Windows is required. Same constraint Husky/pre-commit have |
| Module path auto-derivation breaks when github_owner is set but contains special chars | The slug rules already validate `--project-name` (regex `^[a-z][a-z0-9-]*$`). Apply the same regex to `--github-owner` + `--github-repo` rendering — but that's stricter than GitHub allows. Trade-off: trust the user passed sensible values; render verbatim. If breakage emerges, add validation in a follow-up |
